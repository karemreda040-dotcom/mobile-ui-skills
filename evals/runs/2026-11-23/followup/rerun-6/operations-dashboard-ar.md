# لوحة العمليات اليومية — مواصفة تنفيذية (RTL)

> جميع الأرقام والأسماء وحالات التنبيه في هذه الوثيقة **بيانات مثال للتصميم فقط**، وليست بيانات تشغيلية أو ادعاءات عن منتج حقيقي.

## مهمة الشاشة ونطاقها

الشاشة هي نقطة قراءة سريعة لمشرف عمليات في بداية المناوبة: تحديد ما يحتاج تدخلاً أولاً، ففهم اتجاه العمل، ثم فتح التفاصيل. ليست شاشة إدارة إعدادات، ولا تحاول تنفيذ إجراءات حساسة من لوحة القراءة.

- **المنصة المفترضة:** Android Material 3 مع Jetpack Compose؛ `LayoutDirection.Rtl` للواجهة العربية.
- **مسار الدخول/الخروج:** تُفتح من وجهة «العمليات»؛ زر الرجوع يعيد إلى مستوى التنقل السابق. الضغط على تنبيه أو بند زمني يفتح تفصيله. لا يوجد إجراء أساسي ثانٍ على هذه الشاشة.
- **زمن البيانات:** يظهر نص «آخر تحديث: ١٠:٣٠ ص» بالصيغة المحلية، مع تسمية المصدر/التحديث الفعلي من التطبيق عند التكامل. لا تستخدم الشارة اللونية وحدها للدلالة على الحالة.

## بنية المكونات والحالات

| المكوّن | البنية والسلوك | الحالات المطلوبة |
|---|---|---|
| `OperationsDashboardScreen` | `Scaffold` يستوعب system/gesture insets؛ `LazyColumn` بأقسام متتالية وpadding أفقي 16 dp | تحميل أولي، خطأ شاشة كامل، بيانات جزئية/قديمة، نجاح |
| `DashboardAppBar` | عنوان `العمليات اليومية` في موضع البدء الدلالي؛ زر رجوع Material بعلامة سهم مرآة في RTL، هدف 48×48 dp | عادي، pressed، focus؛ عنوان طويل يلتف بدلاً من القص |
| `ShiftSummary` | سطح واحد بلون `surface`/حد خفيف، داخله 3 عناصر KPI متساوية العرض. كل عنصر: قيمة، تسمية، ونص حالة إن وجد | تحميل skeleton مطابق، لا بيانات «لا توجد طلبات للمناوبة»؛ لا تعامل KPI كزر إلا إذا فتحت قائمة مفلترة |
| `AttentionList` | قائمة صفوف 56 dp على الأقل، رمز تحذير غير زخرفي + عنوان + شرح + شيفرون اتجاهي مرآة؛ الصف كله هدف لمس | تحذير، خطأ مزامنة قابل لإعادة المحاولة، لا تنبيهات: «لا توجد مسائل تحتاج متابعة الآن» |
| `FlowChart` | عنصر رسم متاح: عنوان ووحدة ومحاور/علامات نقطة مختلفة بالشكل، ثم ملخص نصي مكافئ للبيانات | تحميل skeleton، فارغ، جزئي، خطأ مع زر «إعادة المحاولة» |
| `ActivityTimeline` | قائمة زمنية حديثة؛ نقطة 12 dp وخط رابط خافت بين العناصر (لا تعتمد عليه كمعنى وحيد)؛ الوقت منفصل عن النص | تحميل، فارغ «لا نشاط مسجل في الفترة المعروضة»، خطأ/إعادة محاولة |

## بيانات المثال والعقد المقترح

لا تضمّن هذه القيم في الإنتاج. يستبدلها مستودع/Use Case فعلي، مع وقت التحديث والمنطقة الزمنية والحالة.

```kotlin
// Example-only preview fixture — not production data.
data class OperationsSnapshot(
    val updatedAt: Instant,
    val isStale: Boolean,
    val kpis: List<Kpi>,
    val alerts: List<OpsAlert>,
    val flow: List<FlowPoint>,
    val timeline: List<TimelineEvent>
)
data class Kpi(val id: String, val value: Int, val label: String, val status: KpiStatus?)
data class OpsAlert(val id: String, val severity: Severity, val title: String, val detail: String, val action: AlertAction?)
data class FlowPoint(val time: Instant, val requestsPerHour: Int)
data class TimelineEvent(val id: String, val time: Instant, val title: String, val detail: String?)
```

معالجة العرض:

- اعرض القيم بواسطة `NumberFormat.getIntegerInstance(ar-EG)` أو locale الحساب المختار؛ لا تحوّل كل الأرقام قسراً إلى نمط واحد.
- اعرض الوقت عبر formatter محلي وبمنطقة زمنية تأتي من السياق التشغيلي. الأرقام/الأوقات داخل المخطط تبقى مرتبة زمنياً من اليمين إلى اليسار فقط إن كان ذلك هو اصطلاح المنتج المعلن؛ وإلا فالترتيب الزمني المألوف للمخطط يظل ثابتاً ويُعلن بوضوح.
- قيمة KPI لا تعني وحدها «جيد/سيئ». إن كانت هناك عتبة حقيقية، يوفّر المصدر `status` والنص المحلي. في المثال، «٣ متأخرة» نص وصفي مكمل للون التحذير والرمز.

## توجيه التخطيط والرموز

- **شبكة الهاتف:** هامش خارجي 16 dp، فجوة العناصر المرتبطة 8/12 dp، وفجوة القسم 24 dp؛ لا تعتمد على مساحات بطاقات متكررة لتكوين الأقسام.
- **النوع:** خط نظام Android مع دعم عربي؛ العنوان 24/32 sp semibold، عناوين الأقسام 20/28 sp semibold، قيمة KPI 20/28 sp semibold، النص الأساسي 16/24 sp regular، والنص المساند 14/20 sp regular. لا letter-spacing موجب مع العربية.
- **الألوان:** خلفية `#F7F7F7`، سطح `#FFFFFF`، نص أساسي `#171717`، ثانوي `#5F6368`، أساسي `#2563EB` للروابط/التفاعل، وتحذير `#B54708` مع رمز ونص. لا تدرجات أو glass أو ظلال كبيرة. على الوضع الداكن استخدم أدوار اللون الداكنة لا انعكاساً مباشراً.
- **الأشكال:** radius 16 dp للسطح الملخّص، 12 dp فقط للمكوّنات التفاعلية التي تحتاج حاوية. لا pills ولا بطاقات متداخلة.
- **RTL:** استخدم `start/end` و`Alignment.Start/End`، وليس `left/right`. تُعكس أسهم الرجوع/الشيفرون، ولا تُعكس رموز التحذير أو التحديث أو مخطط له اتجاه نطاق زمني معلن. السرد والقراءة يبدأان من اليمين؛ الأرقام المختلطة، المعرفات، ورموز الطلب تُعزل bidi عند عرضها.

## استجابة الحجم، الإدخال، وإتاحة الوصول

- عند عرض أقل من 360 dp، يبقى صف KPI في عمودين ثم عنصر واحد في صف جديد؛ لا تُصغّر النص أو تقصّ التسميات. من 600 dp فما فوق، استخدم عرض محتوى أقصى 720 dp مع تمركزه، واحتفظ بقائمة الخط الزمني في عمود واحد؛ لا تمدد مخطط الهاتف بلا حد.
- عند scale 2×، تكبر صفوف KPI والتنبيهات والخط الزمني مع المحتوى؛ لا تُثبّت الارتفاعات سوى أهداف اللمس الدنيا. تسمح `LazyColumn` بالتمرير ويحافظ `Scaffold` على insets. عند فتح لوحة تفاصيل/مرشح مستقبلي، طبّق `imePadding` وابق التحكم النشط مرئياً.
- كل صف قابل للضغط 48×48 dp على الأقل، مع ripple وحالة focus/pressed واضحة. الرموز الزخرفية `contentDescription = null`؛ رموز التحذير تملك وصفاً عربياً إذا لم يكن النص مجاوراً كافياً.
- قراءة TalkBack: العنوان، آخر تحديث، كل KPI مع تسمية وحالة، التنبيه مع شدته وإجراءه، ثم «مخطط تدفق الطلبات: ...» وملخصه النصي، ثم النشاط بترتيب زمني معلن. لا تعتمد على موضع النقطة أو لون الخط في فهم المخطط.
- التباين: نص صغير/عادي 4.5:1 على الأقل؛ رمز/خط كبير 3:1 على الأقل. حالة «قديم» تضيف نص «قديمة» ورمزاً إلى جانب اللون.

## حالات التحميل والفشل والبيانات الجزئية

1. **تحميل أولي:** skeleton واحد لملخص KPI و2 صفوف تنبيه وموضع مخطط؛ لا دوارات كثيرة مستقلة.
2. **فشل شاشة كامل:** عنوان «تعذر تحميل لوحة العمليات»، وصف موجز، وزر واحد «إعادة المحاولة». يبقى زر الرجوع متاحاً.
3. **بيانات جزئية:** اعرض البيانات المتاحة. بجوار القسم الفاشل رسالة داخلية مع «إعادة المحاولة»، ولا تمسح الأقسام السليمة.
4. **قديمة/offline:** احتفظ بآخر snapshot مع «البيانات قديمة منذ …» وإجراء إعادة المحاولة إذا كان له معنى؛ لا تعِد بصفّ تغييرات دون دعم حقيقي.
5. **فارغ:** رسائل محددة لكل قائمة/مخطط، لا صورة افتراضية ولا عبارات تحفيزية عامة.

## خطة التنفيذ المختصرة

1. عرّف `UiState` sealed (Loading, Content, Partial, Error) في ViewModel وربطه بمصدر snapshot الحقيقي عند توفره.
2. نفّذ `Scaffold` + `LazyColumn` ثم المكونات أعلاه باستخدام Material 3 وsemantic tokens؛ مرّر callbacks بدلاً من وضع منطق شبكة في composables.
3. استخدم `Canvas` بسيطاً للمخطط مع نقاط/خط ومحاور وتسميات، لكن اجعل `ChartSummary` النصي جزءاً من شجرة semantics. لا تضف مكتبة رسم من أجل هذا المخطط الصغير.
4. أضف preview fixtures باسم واضح `example*` فقط، واختبارات Compose للتنقل، حالات الفشل، Arabic RTL، scale 2×، والمحاور/الملخص للنقاط.
